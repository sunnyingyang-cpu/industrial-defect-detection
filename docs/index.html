§ 01 · PROBLEM-DRIVEN DESIGN

三个产线痛点，三处架构改造

先看产线上什么在漏检，再决定改网络的哪里——每一次改动都对应一个明确的工业问题，全部以独立 yaml 配置提供，可单独验证、可 ablation。

PAIN 01 · 尺度
缺陷极小
划痕宽度常 < 5px，P3 层（8× 下采样）难以保留细节
▼ 针对性改造
+ P2 小目标检测头
4× stride 高分辨率特征，手工锚框 + autoanchor 微调，提升亚像素级召回
PAIN 02 · 对比度
低对比度 / 易漏检
轧入氧化皮等条带缺陷与背景灰度几乎连续，卷积局部感受野不够
▼ 针对性改造
+ C3TR Transformer
neck 引入自注意力，强化全图上下文判别
PAIN 03 · 尺度跨度
点状 → 面状跨度大
从点状夹杂到成片斑块，单一尺度网格无法统一覆盖
▼ 针对性改造
+ P6 多尺度配置
P3–P6 四尺度统一检测，配多组锚框对照实验
设计哲学：不是把所有 trick 堆上去，而是让每个架构决策都能回答"它解决哪个产线痛点"—— 6 套配置（P2 / P6+TR / 4l / 4lm / 3l / 5l）构成完整的消融矩阵。

§ 05 · THE HARD CASE

crazing：一场严重的漏检 RECALL ≈ 0

crazing · 龟裂P = 1.00* / R ≈ 0.00 · mAP 0.261

* 这组数字的含义：模型在当前置信阈值下几乎不预测该类——是严重漏检，不是误检。 敢把它放在第一行讲，是因为根因可以一条链讲清楚：

CAUSE 1 · 特征重叠
网状细纹与钢材本底纹理在特征空间高度混杂——Canny 边缘图上细碎边缘密布，缺陷与背景难以分离
→
CAUSE 2 · 传统分割失效
光照不均下 Otsu 全局阈值直接失效（半幅图像全白），Adaptive 阈值同样被背景淹没
→
CAUSE 3 · 形态学无力回天
连通域分析输出 160 个碎片，简单后处理拼不出完整缺陷区域

混淆矩阵同样佐证：对角线外的混淆主要发生在 crazing / scratches / rolled-in_scale 之间—— 条状与网状缺陷在特征空间彼此纠缠，这正是 §08 路线图的出发点。

处方已开，待煎 FIX PREPARED · PENDING RUN

针对性超参 data/hyp.opt.yaml 已就绪：fl_gamma: 2.0（Focal Loss 聚焦难例）+ hsv_v: 0.6(亮度/对比度扰动) + mosaic: 0.5（降低对小目标的过度压缩），并以 --img 800 高分辨率复训—— 目标是 crazing 与 rolled-in_scale 的召回，同时守住整体 mAP。

§ 06 · CLASSICAL CV × DEEP LEARNING

传统图像处理：被实验定位过的工具

CLAHE、Gamma、双边滤波、Canny、Top-Hat / Black-Hat、开闭运算、Otsu、连通域—— 每类缺陷跑完整 12 步管线（tools/preprocess_demo.py），再用 GLCM / LBP 纹理特征做对照。 传统 CV 不做检测器，它的角色由实验说了算：

三种角色

  • R1训练数据增强——CLAHE / 形态学扰动加入训练分布，提升难例类召回（推荐用法）
  • R2可选推理预处理——提升低对比度输入可辨识度（有边界，见右）
  • R3特征工程基线——GLCM 纯 numpy 实现（对比度/同质性/能量/相关度）+ LBP，验证深度特征是否学到本质差异
GLCM 洞察：patches 对比度最高、inclusion 能量最高、rolled-in_scale 同质性最高—— 纹理特征"看得见"差异，却填不上 mAP 的沟，与深度学习弱项形成交叉印证。

决定性实验：CLAHE 硬加在推理期 同一权重 · 同一阈值

crazing 响应提升↑ conf 0.11 → 0.32

CLAHE 让网状细纹浮现，最高置信度提升近 3 倍——增强有效。

但引入成簇误检✗ patches / inclusion 误报

背景纹理被同步放大，12 框中混入多个异类误检；rolled-in_scale 上效果亦不稳定—— 推理期硬加不是可靠方案。

结论：增强应进入训练分布（数据增强协同设计），而不是推理时的滤镜—— 这个边界是跑出来的，不是背出来的。
